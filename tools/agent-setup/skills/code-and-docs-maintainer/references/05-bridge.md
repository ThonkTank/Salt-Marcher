# Verbleibende Wissenslücken schließen

Fragen erst aus zugelassenen aktuellen Projektchats oder einem konkreten
Entwicklungsweg ableiten. Bereits erschlossene Quellen und zuständige Dokustelle
laden. Kein vorsorglicher Fragenkatalog und keine Erklärung je Funktion.

Prüfe zuerst, ob bessere Benennung/Struktur oder ein naher Warum-Kommentar die
Hürde im Code beseitigen sollte. Dies im passenden Modus bearbeiten lassen,
statt schlechte Struktur durch Markdown zu erklären. Aus einem missverständlichen
Arbeitsverlauf keine fehlende Fähigkeit oder neue Anforderung erfinden.

Nur die verbleibende Brücke dokumentieren: Einstieg einer Änderung, verbundene
Schichten/Verträge, übergreifende Gründe, Entwicklungs-/Diagnose-/Prüfweg.
Bestehenden zuständigen Ort nutzen und direkt auf Code verweisen; keine zweite
APIliste oder Nacherzählung des ganzen Ablaufs.

Zeichenvergleich nur mit bereits bekannten passenden Recherchepfaden. Für eine
Kennzahl keine eigene Quellpfad-Untersuchung beginnen. Anforderungen und Gründe
ohne entsprechende Codeantwort sind nicht künstlich vergleichbar.

Fertig: die reale Frage ist richtig und passend auffindbar beantwortet, ohne
ersetzbare Wiederholungen. Tatsächliche spätere Nutzung bleibt eine getrennte
Beobachtung; dafür keine zusätzlichen Evaluationsagenten starten.
