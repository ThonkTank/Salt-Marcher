# Code auffindbarer machen

Beginne bei einer realen Entwicklungsaufgabe und ihrem beobachteten Suchweg oder
beim nächsten ungeprüften Codebereich. Erst Dateistruktur, Suchtreffer und
Einstiegspunkte laden; konkrete Aufrufer/Verbraucher nach Bedarf. Keine vollständige
Architekturanalyse als Vorbedingung.

Zeigen Dateinamen, Module, Exporte und Weiterleitungen den fachlichen Besitzer und
den tatsächlichen Einstieg? Falsche Suchannahmen von versteckter Zuständigkeit
trennen. Die konkrete Hürde beheben; keine breite Umbenennungswelle, erzwungene
Packagehierarchie oder zusätzliche Registry.

Eine Verschiebung muss den ganzen Weg verbessern. Neue Kleinstdateien dürfen
Sucharbeit nicht bloß verlagern. Vor dem Entfernen scheinbar unbenutzter Einstiege
dynamische Aufrufe, Werkzeuge und externe Bindungen prüfen. Bei Überschneidung
mit laufender fremder Arbeit eine unabhängig abschließbare Änderung wählen.

Verbraucher, Imports, Tests und vorhandene Quellenverweise mitziehen. Fertig:
Einstieg und Besitzer sind nachvollziehbar auffindbar, kein halbfertiger
Parallelweg bleibt; passende Prüfung und Veröffentlichung sind abgeschlossen.
Weniger Dateien oder erfolgreicher Import allein beweisen keinen Nutzen.
